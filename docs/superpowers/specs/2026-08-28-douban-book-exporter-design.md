# 豆瓣图书导出 Chrome 扩展设计

## 1. 目标

开发一个 Manifest V3 Chrome 扩展，使用当前 Chrome 中已登录的豆瓣会话，导出当前用户标记为“读过”“想读”“在读”的全部图书。扩展必须保守限速、在验证码或访问限制出现时立即暂停，并能从已持久化的断点继续。

导出文件为 UTF-8 CSV，默认写入 Chrome 的默认下载目录（通常为 `~/Downloads`），也允许用户通过系统目录选择器授权任意文件夹并记住该选择。

## 2. 非目标

- 不读取、展示、复制或导出 Cookie 值。
- 不提交用户名、密码或执行登录操作。
- 不绕过验证码、403、429 或豆瓣的其他访问限制。
- 不导出长篇书评、读书笔记、书摘、标签或豆瓣公共评分。
- 不上传用户数据，不接入遥测、统计或远程服务。
- 首个版本不发布到 Chrome Web Store，只提供源码、构建产物生成方式和本地加载说明。

## 3. 导出数据模型

CSV 每本书一行，列顺序固定为：

1. `状态`：`读过`、`想读` 或 `在读`。
2. `标题`。
3. `ISBN`。
4. `页数`。
5. `作者`：多人时保留豆瓣页面显示顺序，并使用 ` / ` 连接。
6. `出版社`。
7. `出版时间`：保留豆瓣页面原始文本，不推断缺失的日或月。
8. `简介`：保留段落换行，折叠纯布局空白。
9. `标记时间`：保留个人列表显示的日期精度。
10. `我的评分`：整数 `1` 到 `5`；未评分时为空。
11. `我的短评`：保留用户文字和换行；未填写时为空。
12. `评价时间`：有评分或短评时填写；无评价时为空。
13. `评价时间来源`：`独立时间`、`标记时间回退` 或空值。
14. `豆瓣链接`：规范化的 `https://book.douban.com/subject/<id>/` 地址。

若列表页明确提供独立的评价时间，则 `评价时间` 使用该值并标记为 `独立时间`。否则，只要存在评分或短评，就回退为 `标记时间` 并标记为 `标记时间回退`。首个版本不会为了寻找独立评价时间额外遍历每本书的公共短评分页，因为这会显著增加请求数和验证码风险。

同一 subject ID 在一次任务中只导出一行。若抓取期间用户修改状态导致同一本书出现在多个列表中，保留抓取时间较晚的状态，并在任务摘要中记录重复状态警告。

## 4. 技术方案

### 4.1 技术栈

- Chrome Extension Manifest V3。
- TypeScript、Vite、原生 HTML/CSS。
- Vitest、jsdom、fake-indexeddb。
- 最低 Chrome 版本为 116。

不使用 UI 框架，不加载远程脚本，生产构建的全部代码均包含在扩展包内。

### 4.2 权限

Manifest 仅申请以下能力：

- `host_permissions`：`https://*.douban.com/*`，用于向豆瓣发起带当前浏览器会话的请求。
- `downloads`：将 CSV 保存到 Chrome 默认下载目录。
- `offscreen`：在隐藏扩展文档中使用 `DOMParser` 并运行可恢复的抓取循环。
- `alarms`：检测运行中的离屏任务是否意外中止，并触发恢复检查。
任务状态、图书数据、界面设置和目录句柄均保存在扩展源自己的 IndexedDB，因此不额外申请 `storage` 权限。扩展不申请 `cookies` 权限；所有请求使用 `credentials: "include"`，由 Chrome 根据豆瓣主机权限和当前 Cookie 策略决定是否携带现有会话 Cookie。

### 4.3 组件边界

#### 管理页

点击扩展图标后打开一个独立的扩展管理页。管理页负责：

- 展示登录检查、抓取阶段、进度、下一次请求时间和最近错误。
- 发出开始、暂停、继续、重新开始和导出命令。
- 在用户手势中打开系统目录选择器。
- 检查已保存目录句柄的权限；权限失效时重新请求授权。
- 从 IndexedDB 读取稳定快照、生成 CSV，并直接调用 `chrome.downloads` 或 File System Access API 写入文件，避免把大型 CSV 通过运行时消息传递。
- 订阅任务状态更新，但不承担抓取循环。

#### Service Worker

Service Worker 负责 Chrome 生命周期与扩展 API 协调：

- 点击扩展图标时创建或聚焦管理页。
- 创建、查询和关闭离屏文档。
- 处理 `chrome.alarms` 健康检查。
- 在 Chrome 启动时将上次仍处于 `checking_auth`、`discovering_lists` 或 `enriching_details` 的任务转换为可继续的 `paused` 状态，避免重启后未经用户确认立即访问豆瓣。

Service Worker 不把任务状态保存在全局变量中。

#### 离屏抓取器

离屏文档使用 `DOM_PARSER` 原因创建，负责：

- 使用当前登录会话请求豆瓣页面。
- 解析登录身份、个人图书列表和图书详情。
- 执行单并发限速、退避和请求结果分类。
- 在每个提交点将记录和游标原子写入 IndexedDB。
- 通过 `chrome.runtime` 向管理页和 Service Worker 发布状态变化。

管理页关闭后，处于身份检查、列表发现或详情补全阶段的离屏抓取器继续工作。任务暂停、完成或不可恢复失败后关闭离屏文档。

#### 纯逻辑模块

以下逻辑与 Chrome API 隔离，以便直接单元测试：

- 列表页与详情页解析器。
- 状态机和任务游标推进。
- 限速、抖动和重试决策。
- 数据合并、重复 subject ID 处理和字段规范化。
- CSV 序列化与公式注入防护。

#### IndexedDB 仓储

IndexedDB 是任务事实来源，包含以下对象仓库：

- `jobs`：当前任务状态、阶段、用户 ID、三个列表游标、队列位置、计数、限速状态、最近错误和时间戳。
- `records`：以 subject ID 为主键的图书记录、列表字段、详情字段、完成状态和警告。
- `settings`：用户授权的目录句柄及非敏感偏好。

写入一本书时，在同一个事务中更新 `records` 和 `jobs` 的队列游标。只有事务成功后才认为该书完成，因此恢复时不会跳过未落盘的记录。

## 5. 抓取流程

### 5.1 身份检查

1. 请求 `https://www.douban.com/mine/`，允许跟随重定向。
2. 从最终 URL 或返回页面识别当前用户 ID。
3. 若跳转到登录页、页面缺少用户标识或会话 Cookie 未被发送，则任务进入 `auth_required`，提示用户先在普通豆瓣标签页登录并确认扩展拥有豆瓣站点访问权限。
4. 扩展不读取登录表单，也不保存账号信息。

### 5.2 列表发现阶段

按 `读过 -> 想读 -> 在读` 顺序访问当前用户的 `collect`、`wish` 和 `do` 分页。每个列表项提取：

- subject ID、规范化详情 URL 和标题。
- 当前状态。
- 标记日期。
- 我的评分和我的短评。
- 页面存在时的独立评价时间。

每完成一个列表页就提交游标与新发现记录。解析器同时识别“正常空列表”和“页面结构无法识别”；只有前者会结束当前状态的分页。

### 5.3 详情补全阶段

列表阶段完成后，根据去重后的 subject ID 队列逐本访问详情页，提取 ISBN、页数、作者、出版社、出版时间和简介。以下情况允许字段为空并继续：

- 豆瓣条目本身未提供 ISBN、页数、出版社、出版时间或简介。
- 页面明确是图书详情页，但只缺少部分元数据。

若页面无法确认是对应的图书详情页，或核心结构整体消失，则暂停为 `parse_error`，避免静默产生大量空数据。

### 5.4 完成与部分导出

所有列表页和详情队列完成后，任务进入 `completed`。以下状态允许用户显式导出当前已完成数据，并在文件名中加入 `partial`：

- `paused`。
- `captcha_required`。
- `rate_limited`。
- `auth_required`。
- `parse_error`。
- `failed`。

部分导出不改变任务状态，用户仍可在问题解决后继续。

## 6. 限速与访问限制处理

### 6.1 正常节奏

- 始终单并发，任何时刻最多存在一个豆瓣请求。
- 两次请求之间随机等待 4 到 8 秒。
- 每完成 20 次豆瓣请求，额外随机休息 45 到 90 秒。
- 等待时间和下一次允许请求时间持久化，离屏文档意外重建后不会绕过尚未结束的冷却期。

管理页只展示预计时间，不允许用户把限速调得更激进。

### 6.2 可重试错误

网络错误、超时和 HTTP 5xx 使用以下退避序列：

1. 等待 30 秒。
2. 等待 2 分钟。
3. 等待 10 分钟。

同一请求三次重试仍失败时进入 `failed`，保存目标 URL、错误类别和重试次数。

### 6.3 禁止自动重试的错误

以下情况立即停止抓取并持久化断点：

- HTTP 403：进入 `captcha_required`，并在错误详情中记录 `forbidden` 分类。
- HTTP 429：进入 `rate_limited`。
- 页面包含豆瓣安全验证、验证码或异常请求特征：进入 `captcha_required`。
- 登录失效：进入 `auth_required`。
- 页面结构无法可靠识别：进入 `parse_error`。

用户必须处理页面提示后手动点击继续。扩展不会自动刷新验证码页、更换 User-Agent、代理、Cookie 或使用其他规避手段。

## 7. 任务状态机与恢复

任务状态包括：

- `idle`
- `checking_auth`
- `discovering_lists`
- `enriching_details`
- `paused`
- `auth_required`
- `captcha_required`
- `rate_limited`
- `parse_error`
- `failed`
- `completed`

用户点击暂停后，不取消已经发出的请求；该请求完成并提交当前断点后进入 `paused`。用户点击继续时，先重新验证登录态和持久化冷却时间，再从尚未提交的列表页或详情项开始。

关闭管理页不暂停任务。关闭 Chrome、重新加载扩展或更新扩展时，上次处于运行阶段的任务在下次打开时显示为已暂停，必须由用户点击继续。Service Worker 在同一 Chrome 会话内意外休眠时，`chrome.alarms` 健康检查可重新创建离屏文档，并从 IndexedDB 恢复仍处于身份检查、列表发现或详情补全阶段的任务。

“重新开始”需要二次确认。确认后清除当前任务和记录，但保留已授权的下载目录设置。

## 8. CSV 与文件写入

### 8.1 CSV 格式

- 文件以 UTF-8 BOM 开始。
- 使用 CRLF 行结束符。
- 所有字段统一使用双引号包裹，字段内部的双引号写成两个双引号。
- 单元格中的换行原样保留。
- 为防止电子表格公式注入，去除判断用的前导空白后，若文本首字符为 `=`、`+`、`-`、`@`、制表符或回车，则在原始单元格值前添加单引号。
- 空值导出为空字符串。

### 8.2 文件名

完整文件名为：

`douban-books-<安全化用户名>-YYYYMMDD-HHmmss.csv`

部分文件名为：

`douban-books-<安全化用户名>-partial-YYYYMMDD-HHmmss.csv`

用户名中的路径分隔符、控制字符和平台不允许字符替换为下划线。

### 8.3 默认目录与自定义目录

- 默认使用 `chrome.downloads.download()`，文件保存到 Chrome 默认下载目录。
- 自定义目录通过管理页中的 `showDirectoryPicker()` 获取用户授权，并将目录句柄存入 IndexedDB。
- 每次写入前调用权限检查；若权限为 `prompt`，只能在用户点击导出产生的手势中请求权限。
- 权限被拒绝或句柄失效时不静默回退，页面明确提示用户重新选择目录或改用默认下载目录。
- 生成 CSV 前先从 IndexedDB 读取稳定快照；导出期间新完成的记录不混入当前文件。

## 9. 管理页交互

管理页展示：

- 当前用户和登录状态。
- 当前阶段与任务状态。
- 已发现书籍数、详情完成数、失败数和警告数。
- 当前正在处理的书籍或列表页。
- 下一次请求预计时间。
- 最近错误及用户可采取的操作。
- 默认目录或已授权自定义目录的显示名称。

主要操作：

- `开始导出任务`
- `暂停`
- `继续`
- `导出 CSV`
- `选择目录`
- `使用默认下载目录`
- `重新开始`

按钮根据状态启用或禁用，防止并发启动两个任务。验证码、限速、登录失效和解析错误使用不同提示，不把所有异常合并为“导出失败”。

## 10. 安全与隐私

- 只请求豆瓣 HTTPS 域名，不申请所有网站访问权限。
- 不使用 `chrome.cookies` API，不记录请求头或 Cookie。
- HTML 仅通过 DOM 查询和 `textContent` 提取，不把豆瓣返回的 HTML 注入扩展页面。
- 管理页使用静态 DOM 创建和文本节点，不使用不可信 `innerHTML`。
- CSV 对电子表格公式入口字符做中和处理。
- IndexedDB 仅在本地保存用户导出任务；卸载扩展后数据随扩展源删除。
- 不提供加速选项，不尝试隐藏自动化特征或规避豆瓣限制。

## 11. 测试策略

### 11.1 解析器测试

使用手工整理、去除私人数据的 HTML fixture 覆盖：

- `collect`、`wish`、`do` 三种列表。
- 五种星级、无评分、有短评、无短评和文本换行。
- 多作者、缺少 ISBN、缺少页数、缺少出版社、缺少出版时间和缺少简介。
- 正常空列表、登录页、403/429 分类输入、验证码页面和无法识别的结构。
- 简介展开与未展开时的常见 DOM 结构。

### 11.2 纯逻辑测试

- 状态机只允许合法转换。
- 重复 subject ID 只产生一行，并记录状态冲突警告。
- 评价时间独立值优先、标记时间回退和无评价留空。
- 固定随机数和虚拟时钟下，正常抖动、每 20 次冷却及三档退避精确可验证。
- 403、429、验证码、登录失效和解析错误不进入自动重试。
- CSV 的 BOM、CRLF、引号、逗号、换行、中文和公式中和行为。

### 11.3 仓储与恢复测试

使用 fake-indexeddb 验证：

- 记录与游标在同一事务提交。
- 事务失败时游标不会前移。
- 列表页和详情项完成后恢复不会重复请求。
- 暂停、离屏文档重建和浏览器重启后的状态转换。
- 部分导出只读取已经提交的稳定记录。
- 重新开始清除任务数据但保留目录设置。

### 11.4 Chrome 适配器测试与人工验收

通过窄接口模拟 `chrome.runtime`、`chrome.offscreen`、`chrome.alarms`、`chrome.downloads` 和 File System Access API，验证消息和错误映射。最终执行：

- 单元测试。
- TypeScript 类型检查。
- Vite 生产构建。
- 构建产物 manifest 校验。
- `git diff --check`。

真实登录 Cookie、豆瓣当前私有列表、Chrome 目录授权和实际下载需要在 Chrome 中加载 `dist/` 后人工验收。当前开发环境没有可连接的 Chrome 会话，因此完成报告必须明确区分自动验证结果与未执行的真实账号端到端验证。

## 12. 验收标准

1. 已登录用户可以启动三种状态的完整抓取，未登录时得到明确提示。
2. CSV 包含设计中定义的 14 列，中文和多行文字可在常见表格软件中正确打开。
3. 抓取始终单并发并满足 4–8 秒抖动与每 20 次额外冷却规则。
4. 关闭管理页不丢失任务；关闭 Chrome 后能由用户从精确断点继续。
5. 已提交的图书详情不会因恢复而重复请求。
6. 403、429 或验证码出现后不再自动请求豆瓣。
7. 默认目录下载和用户授权的自定义目录写入均有明确成功或失败反馈。
8. 页面字段缺失导出为空，但整体结构异常会停止而不是静默产生错误数据。
9. 所有数据保留在本机，扩展不读取 Cookie 值、不上传数据。
10. 自动测试、类型检查和生产构建通过；真实账号端到端测试状态单独报告。

## 13. 已知风险与应对

- 豆瓣页面结构变化：解析器使用语义标签和多个已知选择器，并在结构整体不匹配时停止；通过更新 fixture 和解析器适配。
- 豆瓣限制扩展来源 Cookie：身份检查会在开始前失败并给出站点访问/Cookie 设置提示，不退回到读取 Cookie 值。
- 大型书库耗时数小时：界面提供预计进度、后台继续、暂停和精确恢复，不通过提高并发缩短时间。
- 抓取期间用户修改收藏状态：按 subject ID 去重，保留抓取时间较晚的状态并记录警告。
- 自定义目录授权失效：写入前重新检查权限，要求用户手势再次授权，不丢弃已经抓取的数据。
